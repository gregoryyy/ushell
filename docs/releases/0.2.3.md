# ush 0.2.3

`ush`, the `//` shell for zsh: ask in plain language, and ush proposes the shell command that
answers it, on your command line. 0.2.3 moves the notes key to Ctrl-N, lets `ush explain` take a
command line without quotes, and fixes `cd` in the `ush>` session.

## Changed since 0.2.2

- **Notes on Ctrl-N:** the plugin's notes key is now Ctrl-N, one keystroke, instead of Ctrl-X n.
  On a command line it runs the line and takes notes on its output; on an empty line, notes on the
  last output; with file names on the line, notes on those files. The plugin takes Ctrl-N only
  where it still has zsh's own meaning (in emacs mode the same as Down; in vi insert mode a
  literal ^N), so a key you bound yourself is kept. `USH_NOTES_KEY` chooses another key, or none
  when empty.
- **`ush explain` without quotes:** with the plugin, everything after `ush explain [-v]` is the
  command line to explain, exactly as you typed it:

  ```sh
  ush explain find . -name "*.log" -mtime +7 | xargs rm
  ```

  explains the whole pipeline. Before, zsh acted on the line first: it expanded globs, removed
  quotes, sent the explanation into `xargs`, and ran whatever followed a `;`. A command line in
  one pair of quotes still works as before. Without the plugin, quote command lines that contain
  `|`, `;`, `>`, `&`, `*`, `$` or quotes.

## Fixed since 0.2.2

- **`cd` in the session:** in the `ush>` session, `cd` didn't move away from the directory the
  session started in, because each line ran in a shell of its own. The session now follows the
  directory a line ends in, whether you typed the line or accepted a proposal. Variables and
  `cd -` still don't carry over from one line to the next.

## Inside

- **Providers as a table:** Anthropic and Ollama are rows of one provider table, each model with a
  profile (effort, thinking, caching, output limit, tool calls written as text). Nothing changes
  in what ush sends; it prepares OpenAI, Mistral and OpenAI-compatible servers for 0.3.0.
- **Source layout:** the sources are in `src/` (`src/go`, `src/py`, `src/shell`, `src/man`), the
  documents in `docs/`. Installed paths and the `~/.zshrc` line are unchanged.

## Install

**Homebrew** (macOS and Linux; builds from the tagged source with Go):

```sh
brew tap gregoryyy/ush
brew trust gregoryyy/ush      # Homebrew loads third-party taps only once trusted
brew install ush              # or, from 0.2.x: brew upgrade ush
```

Then add the line Homebrew prints to `~/.zshrc`, open a new terminal, and run `ush ai configure`.
After an upgrade, open a new terminal so that the new plugin is loaded.

**Release archive:** pick the one for your platform (macOS or Linux, arm64 or amd64), check it, and
run its installer:

```sh
curl -fLO https://github.com/gregoryyy/ushell/releases/download/v0.2.3/ush-0.2.3-darwin-arm64.tar.gz
curl -fLO https://github.com/gregoryyy/ushell/releases/download/v0.2.3/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf ush-0.2.3-darwin-arm64.tar.gz && ush-0.2.3-darwin-arm64/install.sh
```

The installer offers to add the zsh plugin to `~/.zshrc`; open a new terminal afterwards. Then run
`ush ai configure`.

- **From source:** `cd src/go && go build -o ush ./cmd/ush` in the tagged source. The archives are
  built with Go 1.27.4, and with it the build is reproducible: `just ushgo-release 0.2.3` gives
  the published checksums.
- **macOS:** the binary is not signed. Download with `curl` as above; a browser download is
  quarantined (`xattr -d com.apple.quarantine ush` after checking the checksum).

## Security

- **Built with Go 1.27.4:** the release archives are built with Go 1.27.4, which fixes
  GO-2026-6859 in Go's `net/http` (a crash of HTTP servers; ush is only a client).
  `govulncheck` finds no vulnerabilities in them.
- **`ush explain` runs nothing on its line:** with the plugin, `ush explain CMD; rm -rf x` used to
  run the `rm` while you only asked what the command does; now the whole line is the command to
  explain. What goes to the model is unchanged: the command line, with secrets redacted.
- **`cd` in the session** follows the directory a line reports when it ends; it changes nothing
  else. Agent-mode steps still run in the session's current directory.

## Known limitations

- **Agent mode and injected text:** with `--run`, text in command output can steer the model to a
  command ush verifies as read-only, which then runs without asking (SECTEST F8). Changes, secret
  files and network lookups still need approval. On untrusted content, use propose mode (the
  default) or a checker (`-k`).
- **Platforms:** checked on macOS (arm64), with the release archive; on Linux, both test suites
  and the conformance tests pass in GitHub Actions (Ubuntu), but the Linux archives are built
  and not run. Intel Macs are built but not tested.
- **Shells:** zsh only; bash and sh can use the `ush` session. bash, fish and sh come in 0.3.0.
- **Small local models** (llama3.2:3b) often answer agent-mode questions without running anything,
  with made-up numbers; use a model of 8B or more.
- **Homoglyphs** in proposed commands are not flagged.
- **Homebrew builds with Homebrew's Go:** until Homebrew has Go 1.27.4, `brew install ush` builds
  with Go 1.27.3, which `govulncheck` reports for GO-2026-6859 (see Security). The release
  archives don't have this.
