# ush 0.3.0-rc1

`ush`, the `//` shell for zsh: ask in plain language, and ush proposes the shell command that
answers it, on your command line. 0.3.0-rc1 adds OpenAI as a preview provider, lets you pick the
model from the provider's list in `ush ai configure`, keeps one API key per provider, and fixes
answers that went missing when the model offered next steps.

This is a release candidate. The shells release (bash, fish, POSIX sh) moves to 0.4.0.

## Changed since 0.2.4

- **OpenAI, as a preview:** `ush ai configure` offers OpenAI next to Anthropic and a local
  Ollama. ush talks to OpenAI's Responses API, with `gpt-6-astra` as the default model. It has been
  tested against a local stand-in of that API only, never against OpenAI itself, so try it, but
  don't rely on it yet (see Known limitations). An OpenAI model can also be the checker, as
  `openai:MODEL`. Another OpenAI endpoint, such as a company gateway, is set with `openai_url` or
  `USH_OPENAI_URL` (https, or http on this machine).
- **Choose the model from a list:** after the provider and its key, `ush ai configure` lists the
  provider's models, numbered, newest first: Anthropic's and OpenAI's from their APIs (with your
  key), or the models you have pulled into Ollama. Answer with a number or type a name. When the
  list can't be fetched, ush offers a short built-in list. `ush ai models` prints the list.
- **One key per provider:** the Anthropic and the OpenAI key are kept apart, in the macOS
  keychain (one item each) or in `~/.config/ush/credentials`. `ush ai clear-key` removes the
  configured provider's key; `ush ai clear-key openai` removes another one. An existing Anthropic
  key keeps working as it is. `OPENAI_API_KEY` sets the OpenAI key for one shell.

## Fixed since 0.2.4

- **Answers with next steps:** a model sometimes wrote its answer only in its thinking and then
  offered next steps. ush showed the steps but printed no answer, so `ush … > file` and pipes got
  nothing, and history recorded an empty answer. Next steps are now shown only with an answer in
  text; otherwise the model is asked for the answer.

## Install

**Homebrew** (macOS and Linux; builds from the tagged source with Go):

```sh
brew tap gregoryyy/ush
brew trust gregoryyy/ush      # Homebrew loads third-party taps only once trusted
brew install ush              # or, from 0.2.x: brew upgrade ush
```

Then add the line Homebrew prints to `~/.zshrc`, open a new terminal, and run `ush ai configure`.
After an upgrade, open a new terminal so that the new plugin is loaded.

**Release archive:** pick the one for your platform (macOS or Linux, arm64 or amd64), check it, and
run its installer:

```sh
curl -fLO https://github.com/gregoryyy/ushell/releases/download/v0.3.0-rc1/ush-0.3.0-rc1-darwin-arm64.tar.gz
curl -fLO https://github.com/gregoryyy/ushell/releases/download/v0.3.0-rc1/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf ush-0.3.0-rc1-darwin-arm64.tar.gz && ush-0.3.0-rc1-darwin-arm64/install.sh
```

- **From source:** `cd src/go && go build -o ush ./cmd/ush` in the tagged source. The archives are
  built with Go 1.27.4, and with it the build is reproducible: `just ushgo-release 0.3.0-rc1`
  gives the published checksums.
- **macOS:** the binary is not signed. Download with `curl` as above; a browser download is
  quarantined (`xattr -d com.apple.quarantine ush` after checking the checksum).

## Security

- **Keys:** each provider's key goes only to that provider's endpoint, also when listing models,
  and is removed from the environment of the commands ush runs, and redacted from output and
  history. Keys are written to the keychain on stdin, not as arguments.
- **Where requests go:** the banner and `ush ai status` say "go to OpenAI" for the OpenAI
  provider. Requests are sent with `store: false`; OpenAI's reasoning comes back encrypted and is
  kept only in the session file (mode 0600, one hour). Redirects are not followed.
- **Model names from a provider's list** pass the same check as a typed name, so a list can't put
  escape sequences on your terminal.
- **Built with Go 1.27.4;** `govulncheck` found no vulnerabilities in the binary of the release
  checks.

## Known limitations

- **OpenAI is untested against OpenAI itself:** only against a local stand-in of its API. Testing
  it is the release candidate's technical debt (TODO 2.51), owed before 0.3.0.
- **The banner names OpenAI for any OpenAI endpoint:** with `openai_url` or `USH_OPENAI_URL` set
  to another host, it still says "go to OpenAI" (TODO 2.50).
- **Agent mode and injected text:** with `--run`, text in command output can steer the model to a
  command ush verifies as read-only, which then runs without asking (SECTEST F8). Changes, secret
  files and network lookups still need approval. On untrusted content, use propose mode (the
  default) or a checker (`-k`). The fix (TODO 2.23) is not in this release.
- **Local models and the newer tools:** smaller local models often propose a one-line command
  where a larger one would ask back, write a script or offer next steps. llama3.2:3b often
  answers agent-mode questions without running anything.
- **Platforms:** checked on macOS (arm64) with the release archive; on Linux, the Go tests and the
  conformance tests pass in GitHub Actions and in a local Ubuntu container. The Linux archives
  are built, not run. Intel Macs are built but not tested.
- **Shells:** zsh only; bash and sh can use the `ush` session. bash, fish and sh come in 0.4.0.
- **Homoglyphs** in proposed commands are not flagged.
